## 1. Теоретические основы

### 1.1. Постановка задачи

Рассматривается бинарная последовательность длины $N$:

$$
X_1, X_2, \ldots, X_N, \qquad X_i \in \{0,1\}.
$$

Цель исследования — оценка статистических свойств методов измерения зависимости между соседними элементами последовательности в зависимости от её длины, стационарной вероятности единицы $p$ и коэффициента автокорреляции первого порядка $\rho$.

При независимости элементов $\rho=0$. В рассматриваемой марковской модели положительная автокорреляция соответствует повышенной вероятности сохранения текущего состояния. При малых значениях $N$ выборочная изменчивость может затруднять обнаружение зависимости.

### 1.2. Модель генерации

В качестве модели используется однородная цепь Маркова первого порядка с пространством состояний $\{0,1\}$. Матрица переходных вероятностей имеет вид

$$
P = \begin{pmatrix} p_{00} & p_{01} \\ p_{10} & p_{11} \end{pmatrix},
$$

где $p_{ij}=P(X_{t+1}=j\mid X_t=i)$, а сумма элементов каждой строки равна единице.

### 1.3. Параметризация матрицы переходов

Для заданных стационарной вероятности $p=P(X_t=1)$ и автокорреляции $\rho$ используются следующие соотношения:

$$
\begin{aligned}
p_{01} &= p(1-\rho), \\
p_{11} &= p+(1-p)\rho, \\
p_{00} &= 1-p_{01}, \\
p_{10} &= 1-p_{11}.
\end{aligned}
$$

Начальное состояние генерируется согласно распределению Бернулли с параметром $p$. Таким образом, последовательность стационарна с первого элемента; предварительный период стабилизации не требуется.

### 1.4. Предельные случаи

- При $\rho=0$ выполняется $p_{01}=p_{11}=p$; элементы последовательности независимы.
- При $\rho=1$ выполняется $p_{01}=0$, $p_{11}=1$; последовательность сохраняет начальное состояние на всех шагах.

## 2. Параметры эксперимента и ограничения

Параметры эксперимента определены в файле `src/config.py`. Перед запуском `main.py` и `plot_results.py` функция `check_config()` из `src/validator.py` проверяет их корректность и останавливает программу с ошибкой `ValueError`, если значения выходят за математически допустимые пределы. Функция `check_config()` вызывается на уровне модуля (при импорте `main.py` и `plot_results.py`), а не внутри `main()`.

| Параметр | Назначение | Допустимый диапазон | Значения в `src/config.py` |
| :--- | :--- | :--- | :--- |

| **`P_ONES`** (`p_one`) | Стационарная вероятность единицы в цепи $P(X_i = 1)$ | Строго $(0.0, 1.0)$ | `[0.1, 0.3, 0.5, 0.7, 0.9]` |

| **`PLOTS_DIR`** | Каталог для сохранения графиков | Строка с путём к директории | `"results/plots"` |
| **`TARGET_P`** | Срез по $p$ для построения графиков | Любое значение из списка `P_ONES` | `0.3` |
| **`TARGET_RHO`** | Срез по $\rho$ для построения графиков | Любое значение из `RHOS` кроме `0.0` | `0.3` |

### 2.1. Ограничения на автокорреляцию

При неравных стационарных вероятностях состояний (например, $p = 0.1$ или $p = 0.9$) строгое чередование состояний невозможно ($\rho = -1$), поскольку оно соответствует стационарной вероятности $p=0.5$. Формула $\rho_{\min} = \max(-p/(1-p), -(1-p)/p)$ гарантирует, что $0 \le p_{01}, p_{11} \le 1$. Например, для $p = 0.5$ диапазон $[-1.0, 1.0]$, а для $p = 0.1$ и $p = 0.9$ — $[-0.111, 1.0]$.

### 2.2. Параметры визуализации

Параметр `TARGET_RHO` влияет только на графики 1–3 (bias, std, detection). График 4 (false positive) всегда строится по срезу `rho = 0.0`, независимо от `TARGET_RHO`.

## 4. Спецификация программных модулей

### 4.1. `src/generator.py` — Генерация данных

Отвечает за создание синтетических бинарных цепочек с заданными свойствами.

**Интерфейс модуля**

- `build_transition_matrix(p_one, rho)` — формирует и возвращает `np.ndarray` размером $2 \times 2$ с вероятностями переходов.
- `generate_chain(length, p_one, matrix, seed)` — генерирует одномерный массив `chain` из `0` и `1` длины `length`.
  - *Алгоритм работы:* заранее генерирует массив случайных чисел `rand_vals` из равномерного распределения $[0, 1)$. Первому элементу `chain` присваивается значение `1`, если `rand_vals[0] < p_one`. Для каждого последующего индекса `i` определяется предыдущее состояние `prev_symbol = chain[i - 1]` и вероятность перехода `prob_of_one = matrix[prev_symbol, 1]`. Элементу присваивается значение `1`, если `rand_vals[i] < prob_of_one`.

**Обозначения и переменные**

- `p_one` — базовая вероятность появления `1` (доля единиц).
- `rho` — коэффициент автокорреляции первого порядка.
- `p00, p01, p10, p11` — вероятности переходов (`0->0`, `0->1`, `1->0`, `1->1`).
- `matrix` — таблица $2 \times 2$ с вероятностями переходов.
- `length` — длина генерируемой цепочки.
- `seed` — начальное значение генератора случайных чисел (для повторяемости).
- `rng` — объект генератора `np.random.default_rng(seed)`.
- `chain` — итоговый массив из `0` и `1` (`np.ndarray` с `dtype=int`).
- `rand_vals` — массив случайных чисел от `0` до `1` для выбора символов.
- `prev_symbol` — предыдущий элемент в цепочке (`0` или `1`).
- `prob_of_one` — вероятность поставить `1` на текущем шаге.

### 4.2. `src/estimation.py` — Методы оценки зависимости

Принимает сгенерированную цепочку `chain` и оценивает зависимость по её элементам.

**Интерфейс модуля**

- `count_pairs(chain)` — вычисляет число соседних пар `(n00, n01, n10, n11)`.
- `sample_correlation(chain)` — **Метод 1**. Вычисляет выборочный коэффициент корреляции Пирсона $r$ между соседними элементами (оценка $\rho$). При вырожденной цепочке (`denom == 0`) возвращает `np.nan`.
- `estimate_joint_probs(chain)` — **Метод 2**. Вычисляет эмпирические совместные вероятности всех четырёх пар `(P00, P01, P10, P11)`. В эксперименте отслеживается $P(1,1)$.
- `estimate_conditional_probs(chain)` — **Метод 3**. Оценивает вероятности переходов в единицу `(p01_hat, p11_hat)`. Разность `p11_hat - p01_hat` является оценкой $\rho$. При отсутствии соответствующего исходного состояния среди первых $N-1$ элементов возвращает `np.nan` для соответствующей оценки.
- `norm_cdf(x)` — функция стандартного нормального распределения (для статистических тестов).

`norm_cdf` в текущей версии не используется в `main.py` и `metrics.py` — она предназначена для использования как вспомогательная функция для ручных статистических проверок.  

`estimate_conditional_probs` возвращает `np.nan` для `p01_hat` или `p11_hat`, если среди первых $N-1$ элементов отсутствуют `0` (для `p01_hat`) или отсутствуют `1` (для `p11_hat`). В `run_conditional` разность `p11_hat - p01_hat` в этом случае тоже будет `nan`, и соответствующая оценка исключается из расчёта метрик.

**Обозначения и переменные**

- `curr_s`, `next_s` — сдвинутые срезы цепочки `chain[:-1]` и `chain[1:]` (текущий и следующий элементы).
- `n00, n01, n10, n11` — количество встреченных пар (`00`, `01`, `10`, `11`).
- `denom` — знаменатель в формуле корреляции (проверка деления на ноль).
- `r` — выборочный коэффициент корреляции.
- `n_pairs` — общее количество соседних пар (`len(chain) - 1`).
- `n0, n1` — число вхождений символов `0` и `1` (не считая последний символ).
- `p01_hat, p11_hat` — выборочные вероятности переходов `0->1` и `1->1`.

**Расчётные соотношения**

1. **Выборочный коэффициент корреляции (Метод 1):**
   $$
   r = \frac{n_{11} n_{00} - n_{10} n_{01}}{\sqrt{(n_{11} + n_{10})(n_{11} + n_{01})(n_{01} + n_{00})(n_{10} + n_{00})}}
   $$
2. **Совместные вероятности пар (Метод 2, где $n_{\text{pairs}} = N - 1$):**
   $$
   \hat{P}(00) = \frac{n_{00}}{n_{\text{pairs}}}, \quad \hat{P}(01) = \frac{n_{01}}{n_{\text{pairs}}}, \quad \hat{P}(10) = \frac{n_{10}}{n_{\text{pairs}}}, \quad \hat{P}(11) = \frac{n_{11}}{n_{\text{pairs}}}
   $$
3. **Условные вероятности (Метод 3):**
   $$
   \hat{p}_{01} = \frac{n_{01}}{n_{00} + n_{01}}, \quad \hat{p}_{11} = \frac{n_{11}}{n_{10} + n_{11}}, \quad \hat{\rho}_{\text{cond}} = \hat{p}_{11} - \hat{p}_{01}
   $$
4. **Функция стандартного нормального распределения:**
   $$
   F(x) = 0.5 \cdot \left(1 + \operatorname{erf}\left(\frac{x}{\sqrt{2}}\right)\right)
   $$

### 4.3. `src/metrics.py` — Метрики качества оценок

Все функции отбрасывают `np.nan` (`clean = estimates[~np.isnan(estimates)]`), возвращают `None`, если валидных оценок не осталось, и округляют результат до 4 знаков после запятой.

- `calc_bias(estimates, true_value)` — **Среднее смещение (Mean Bias)**: `round(mean(clean) - true_value, 4)`. Целевое значение: `0.0`.
- `calc_std(estimates)` — **Разброс оценок (Std Dev)**: `round(std(clean), 4)`. Показывает случайный разброс оценок между запусками.
- `calc_detection_rate(estimates, threshold)` — **Доля обнаружений (Detection Rate)**: доля запусков при $\rho > 0$, где `abs(clean) > threshold`. Целевое значение: `1.0`.
- `calc_false_positive_rate(estimates, threshold)` — **Ложные срабатывания (False Positive Rate)**: доля запусков при $\rho = 0$, где `abs(clean) > threshold`. При пороге $\text{threshold} = \frac{2}{\sqrt{N}}$ ориентировочный уровень ошибки составляет около **5%** при нормальной аппроксимации.

все метрики сначала отбрасывают `np.nan`, поэтому знаменатель для `calc_detection_rate` и `calc_false_positive_rate` — это **число валидных (не-`nan`) оценок**, а не `N_TRIALS`. Если часть цепочек вырождена (все нули или все единицы), доля считается от меньшего числа.

### 4.4. `src/config.py` — Конфигурация эксперимента

Хранит все управляющие параметры эксперимента и визуализации в одном месте, для централизованного управления экспериментом.

**Обозначения и переменные**

- `LENGTHS` — список длин последовательностей для перебора (например, `[20, 50, 100, 500, 1000]`).
- `P_ONES` — список базовых вероятностей появления `1` (например, `[0.1, 0.3, 0.5, 0.7, 0.9]`).
- `RHOS` — список проверяемых коэффициентов корреляции (например, `[0.0, 0.1, 0.3, 0.5]`).
- `N_TRIALS` — количество повторных симуляций для каждой комбинации параметров (`10_000`).
- `SEED` — начальное начальное значение генератора случайных чисел (`42`) для полной повторяемости результатов.
- `SUMMARY_CSV` — путь к файлу итоговой таблицы (`"results/summary.csv"`).
- `PLOTS_DIR` — директория для сохранения графиков (`"results/plots"`).
- `TARGET_P` — конкретное значение $p$ из списка `P_ONES`, по которому строятся графики.
- `TARGET_RHO` — конкретное положительное значение $\rho$ из списка `RHOS`, по которому строятся графики 1–3. На график 4 не влияет.

### 4.5. `src/validator.py` — Валидация входных данных

Выполняет проверку входных данных, допустимости параметров модели и согласованности конфигурации.

**Интерфейс модуля**

- `check_params(length, p_one, rho)` — проверяет, что `length` — целое число $\ge 2$ (принимается `int` или `np.integer`, но не `bool`), `p_one` лежит строго в $(0.0, 1.0)$, а `rho` находится в допустимых границах $[\rho_{\min}, 1.0]$.
- `check_matrix(matrix)` — проверяет размерность матрицы $2 \times 2$, отсутствие `NaN`/`Inf`, принадлежность элементов отрезку $[0, 1]$ и равенство суммы вероятностей по каждой строке единице (через `np.allclose(..., 1.0)`, то есть с допуском на плавающую точку, а не строгим равенством).
- `check_chain(chain)` — проверяет, что цепочка — одномерный массив `np.ndarray` длиной $\ge 2$, состоящий строго из символов `0` и `1`. `dtype` цепочки не проверяется — достаточно, чтобы все значения были `0` или `1` (проверка через `np.isin(chain, (0, 1))`).
- `check_config(lengths, p_ones, rhos, n_trials, target_p, target_rho)` — валидирует все списки настроек из `src/config.py`, проверяет `N_TRIALS >= 1` и убеждается, что `TARGET_P` и `TARGET_RHO` присутствуют в заданных списках (и `TARGET_RHO != 0.0`). Вызывается на уровне модуля при импорте `main.py` и `plot_results.py`.
- `run_safe_generator(length, p_one, rho, seed)` — обёртка для безопасной генерации цепочки с проверкой параметров, матрицы и результата. При любой ошибке проверки (`check_params`, `check_matrix`, `check_chain`) вызывает исключение `ValueError` с описанием проблемы; не возвращает `None` и не подавляет исключения.
- `run_safe_estimation(estimator_func, chain, *args, **kwargs)` — обёртка для безопасного запуска любого метода оценки после проверки входной цепочки. При ошибке `check_chain` вызывает исключение `ValueError`.

**Обозначения и переменные**

- `min_rho` — математически допустимая нижняя граница корреляции при заданном `p_one`: $\max(-p/(1-p), -(1-p)/p)$.
- `estimator_func` — ссылка на одну из функций оценки из `src/estimation.py`.

### 4.6. `src/main.py` — Управление вычислительным экспериментом

Связывает генератор, методы оценки и расчёт метрик в единый конвейер и сохраняет результаты в CSV-таблицу.

**Интерфейс модуля**

- `summarize(estimates, true_value, threshold, is_dep, has_test=True)` — преобразует массив из `N_TRIALS` оценок в словарь с четырьмя метриками (`Mean Bias`, `Std Dev (Spread)`, `Detection Rate`, `False Positive Rate`). Если `has_test=False`, в столбцы тестов записывает `"-"`.
- `run_correlation(chains, true_rho)` — применяет **Метод 1** (`sample_correlation`) по всем цепочкам серии и сравнивает оценки с истинным `true_rho` при пороге обнаружения $\text{threshold} = \frac{2}{\sqrt{\text{length}}}$, где `length = len(chains[0])` — длина цепочки (не `N_TRIALS`).
- `run_joint(chains, p_one, p11, is_dep)` — применяет **Метод 2** (`estimate_joint_probs`), извлекает долю пар `11` (`p11_joint`) и сравнивает с истинной совместной вероятностью $P(1,1) = p \cdot p_{11}$. Использует `threshold=0.0` и `has_test=False` — порог не используется, столбцы `Detection Rate` и `False Positive Rate` заполняются `"-"`. Для метода 2 рассчитываются только `Mean Bias` и `Std Dev`. Поскольку метод оценивает совместную вероятность, а методы 1 и 3 — автокорреляцию, абсолютные значения смещения и стандартного отклонения не следует интерпретировать как непосредственно сопоставимые оценки точности одного параметра.
- `run_conditional(chains, p01, p11, is_dep)` — применяет **Метод 3** (`estimate_conditional_probs`), вычисляет разность $\hat{p}_{11} - \hat{p}_{01}$ и сравнивает с истинной разностью $p_{11} - p_{01}$ при пороге $\frac{2}{\sqrt{\text{length}}}$.
- `main()` — проверяет конфиг через `check_config()` (на уровне модуля), перебирает все комбинации `(length, p_one, rho)`, генерирует по `N_TRIALS` цепочек и записывает строки в `results/summary.csv`. Для каждой комбинации формируются три строки — по одной на каждый метод. В консоль выводится прогресс: `Серия для длины {length} завершена.`

**Обозначения и переменные**

- `rng` — основной генератор случайных чисел: `rng = np.random.default_rng(SEED)`. Для каждой цепочки берётся `seed=int(rng.integers(0, 2**32 - 1))`, что обеспечивает воспроизводимость при фиксированном `SEED`.
- `output` — объект `Path` для итогового файла `results/summary.csv`.
- `fieldnames` — список заголовков столбцов CSV-таблицы.
- `chains` — список из `N_TRIALS` сгенерированных бинарных цепочек для текущей комбинации параметров.
- `is_dep` — логический флаг наличия зависимости (`True`, если `rho != 0.0`, иначе `False`).
- `threshold` — порог обнаружения $\frac{2}{\sqrt{\text{length}}}$ (соответствует уровню $\approx 2\sigma$).
- `true_p11_joint` — теоретическая совместная вероятность появления пары `11`: `p_one * p11`.
- `true_diff` — теоретическая разность условных вероятностей: `p11 - p01` (численно равна `rho`).

### 4.7. `src/plot_results.py` — Визуализация результатов

Читает сводную таблицу `results/summary.csv` и строит 4 сравнительных графика для выбранного среза параметров.

**Интерфейс модуля**

- `setup_axis(ax, lengths, ylabel, title)` — настраивает логарифмическую шкалу по оси X, подписи осей, заголовок и легенду графика. Логарифмическая шкала по X включается, только если `len(lengths) > 1` и `min(lengths) > 0`.
- `draw_methods(ax, sub, metric_col)` — строит кривые для каждого метода из словаря `METHOD_STYLES`, автоматически пропуская методы с прочерками (`NaN` после приведения типов). Возвращает `True`, если хотя бы один метод был нарисован (то есть в срезе есть валидные данные). Если `False` — график не сохраняется.
- `plot_bias_comparison(df, p_one, rho, lengths, out_dir)` — строит график среднего смещения (`1_bias_comparison.png`) с пунктирной линией идеального нуля.
- `plot_std_comparison(df, p_one, rho, lengths, out_dir)` — строит график разброса оценок (`2_std_comparison.png`).
- `plot_detection_comparison(df, p_one, rho, lengths, out_dir)` — строит график доли обнаруженных зависимостей (`3_detection_rate_comparison.png`).
- `plot_false_positive_comparison(df, p_one, lengths, out_dir)` — строит график доли ложных срабатываний (`4_false_positive_comparison.png`). Всегда фильтрует по `rho == 0.0`, независимо от `TARGET_RHO`; `TARGET_RHO` на этот график не влияет.
- `main()` — проверяет конфиг (на уровне модуля), читает CSV, удаляет существующий каталог `results/plots/` посредством `shutil.rmtree` и создаёт её заново, затем вызывает функции построения всех 4 графиков. Используется стиль `seaborn-v0_8-whitegrid`.

**Обозначения и переменные**

- `METHOD_STYLES` — словарь визуальных настроек (подпись в легенде, цвет, тип линии, маркер, толщина и прозрачность `alpha`, чтобы перекрывающиеся линии Методов 1 и 3 оставались различимыми).
- `sub` — отфильтрованный срез таблицы `DataFrame` для заданных `TARGET_P` и `TARGET_RHO`.
- `out_dir` — объект `Path` для каталога сохранения графиков.

## 5. Порядок выполнения эксперимента

**Зависимости:** `numpy`, `pandas`, `matplotlib`. Для воспроизводимости рекомендуется зафиксировать версии (например, через `requirements.txt`).

Все команды выполняются из корневой каталога проекта (`binary-correlation-benchmark`) как модули Python (`-m`), для корректного разрешения импортов из `src`:

1. **Выполнение вычислительного эксперимента** (повторное выполнение требуется при изменении `LENGTHS`, `P_ONES`, `RHOS`, `N_TRIALS` или `SEED` в `src/config.py`):
   ```bash
   .venv/bin/python -m src.main
   ```

2. **Построение графиков по сформированной таблице:**

   ```bash
   .venv/bin/python -m src.plot_results
   ```

Результаты сохраняются в `results/summary.csv`, а графики — в `results/plots/`.
